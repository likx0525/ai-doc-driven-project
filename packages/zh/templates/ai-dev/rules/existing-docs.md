# existing-docs

> 文档状态：current

## 用途

用于 audit 模式处理目标项目中已经存在的文档。AI 必须先审查和索引现有文档，不得直接创建一套新文档后忽略旧文档。

## 必须扫描

- `README.md`
- `docs/`
- `design/`
- `spec/`
- `requirement/`
- `requirements/`
- `notes/`
- `ai/`
- `.github/`
- Markdown 文档
- 文本文档
- 现有测试说明
- 现有部署说明
- 现有环境说明
- 现有决策记录
- 现有问题记录

## 文档分类

- 项目说明
- 需求说明
- 设计说明
- 架构说明
- 环境说明
- 测试说明
- 部署说明
- 接口说明
- 数据模型说明
- 决策记录
- 临时笔记
- 过期文档
- 无法判断

## 处理方式

- 保留
- 引用
- 摘要合并
- 标记过期
- 待确认
- 建议归档

## 禁止事项

- 不直接删除。
- 不直接覆盖。
- 不擅自移动。
- 不把旧文档内容直接当成当前事实。
- 低可信度或未知可信度文档不得作为开发依据。

## 索引表

| 文件路径 | 文档类型 | 主要内容 | 当前状态 | 可信度 | 建议处理 |
|---|---|---|---|---|---|

当前状态：有效 / 部分有效 / 过期 / 冲突 / 待确认

建议处理：保留 / 引用 / 摘要合并 / 标记过期 / 待确认 / 建议归档

## 冲突记录

冲突必须写入 `docs/ai-dev/PROJECT_AUDIT.md`。如果冲突来自多个 AI 会话、重复编号、旧上下文写回、核心文档并发编辑或 changeset 合并，也必须写入 `docs/ai-dev/concurrency/CONFLICTS.md`。

| 冲突编号 | 文档 A | 文档 B / 代码现状 | 冲突内容 | 影响范围 | 建议处理 | 是否需要用户确认 |
|---|---|---|---|---|---|---|

如需归档旧文档，必须先提出建议，不直接移动。归档目录为 `docs/archive/`，只有用户确认后才允许移动文档。
