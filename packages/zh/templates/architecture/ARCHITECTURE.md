# ARCHITECTURE

> 文档状态：draft

## 用途
记录整体架构目标、边界和约束。

## 架构目标
- 可维护。
- 可测试。
- 模块边界清晰。
- 数据和状态事实来源清晰。

## 当前架构概览
- 待填写：系统组成、主要层级、主要数据流。

## 分层规则
- UI 层负责展示和交互。
- 应用层负责流程编排。
- Domain 层负责核心业务规则。
- 基础设施层负责数据库、外部 API、文件、运行时能力。

## 依赖方向
- 外层可以依赖内层。
- Domain 层不得依赖 UI、数据库、外部 API 或具体框架。

## 状态管理原则
- 避免多个事实来源不清的重复状态。
- 状态变更必须有明确入口和测试。

## 业务规则原则
- 不得在 UI 层编写核心业务规则。
- 同一核心业务规则只能有一个主要实现位置。

## 数据模型原则
- 核心对象、字段、状态值和派生数据必须有清晰含义。

## 禁止事项
- AI 不得只以“能实现当前功能”为目标。
- AI 还必须判断是否破坏模块边界、依赖方向、数据模型、状态一致性和后续可维护性。
- 不得用备注、字符串、魔法值或隐藏字段承载核心逻辑。
- 功能开发和重构默认分开。
